## Changes from beta.3

- Both LangGraph producers retain a confirmed compiled child's parent node
  under its own id at every depth instead of flattening it away. Within the
  requested `depth` budget, the parent node additionally gains a core
  `subgraphId` addressing the child as its own first-class `graphs[]` entry,
  deterministically derived as `parentGraphId:parentNodeId`; a derived id that
  would collide with an existing graph id is never emitted, and the node
  stays opaque with a new `child-graph-id-collision` gap instead. `depth = N`
  now materializes levels `1..N`; level `N`'s own children keep the unchanged
  depth-0 opaque-child contract, and depth-0 output remains byte-identical to
  today's. `expanded-subgraph-metadata` is retired: it can no longer be
  emitted. See
  [ADR 0012](../decisions/0012-nested-graph-identity-traversal-and-compatibility.md).
- Both LangGraph producers now populate `branch`, `sentinel`, and `entry`
  experimental interpretation facts for a materialized child's own nodes,
  using the same [ADR 0008](../decisions/0008-experimental-consumer-interpretation.md)
  evidence rules already used for a root graph — a materialized child is not
  a degraded view. `x-topology-interpretation` advances to revision `"2"` on
  any graph that materializes at least one child, adding a `subgraph` value
  of `materialized-child` (evidence kind `materialized-subgraph-reference`,
  referencing the containing `graphs[].id` and the node's `subgraphId`).
  `opaque-child` is invalid on any node carrying core `subgraphId`, and
  `materialized-child` is invalid without one. Depth-0 documents and any
  document with no materialized node continue to use revision `"1"`
  unchanged. See
  [ADR 0012](../decisions/0012-nested-graph-identity-traversal-and-compatibility.md).
- The Python CLI exposes the `describe` API's traversal depth through
  `agt describe --depth N`, defaulting to `0` (backward compatible, opaque
  children) and accepting only non-negative integers; an invalid, missing, or
  negative value is a usage error (status `2`). `agt describe` output at a
  given depth is equivalent to calling the Python API with the same `depth`,
  including `--strict` status `6` for an actual graph-specific gap. The CLI
  still only imports and describes a module-level compiled-object target; it
  does not invoke the graph or call a factory to build one. See
  [ADR 0007](../decisions/0007-langgraph-owns-the-foundation-cli.md) and the
  [CLI reference](../reference/cli.md).
- A caller whose target object requires a factory (policy, model gateway, or
  other invocation-time argument) is not a supported CLI target; `agt` never
  invokes a factory or accepts factory arguments. An import-safe module that
  constructs and exports the compiled object at import time, without
  invocation-time side effects, remains the supported pattern. See the
  [factory-export recipe](../research/internal-consumer/import-safe-export/README.md)
  and the [upgrade guide](../guides/upgrading-beta.4.md#factory-owned-graphs-and-the-cli-target).
- Positive-depth address correlation (parent identity, repeated child call
  sites, and materialized-child identity) is exercised end to end against the
  current producer, and a real dynamic-interrupt/resume/repeated-attempt
  capture proves the boundary between what the document can state statically
  and what only a runtime observation can confirm. See the
  [internal-consumer research index](../research/internal-consumer/README.md#final-dispositions-issue-154)
  and the [upgrade guide](../guides/upgrading-beta.4.md#topology-vs-dynamic-pauses-approval-validity-and-runtime-effects).

## Publication checklist

- [ ] Create `rc/0.1.0-beta.4` from the reviewed `main` commit that merges
      this candidate preparation; route any RC-only correction through a PR
      targeting that branch.
- [ ] Pass package CI and framework compatibility checks on the frozen commit.
- [ ] Qualify each package with `publish=false`; record the exact receipts
      and digests.
- [ ] Publish the Python specification, then its producer.
- [ ] Publish the npm specification, then its producer.
- [ ] Install every exact registry version in a clean environment and verify
      public APIs, including the depth-materialization and revision-2
      interpretation behavior above.
- [ ] Record artifact URLs, digests, source commit, provenance, and workflow
      receipts here.
- [ ] Create `v0.1.0-beta.4` at the qualified commit, then the GitHub
      prerelease.
- [ ] Update public installation guides from beta.3 to beta.4 only after
      verification.
- [ ] Merge release changes back into main through a PR.

No beta.4 tag or GitHub Release should imply publication before those checks
pass. Do not replace the existing beta.1, beta.2, or beta.3 registry
artifacts. Follow the
[release and partial-publication recovery guide](../releasing.md).
