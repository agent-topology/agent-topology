## Changes from beta.4

### Join identity: deduplication and unambiguous encoding

Both LangGraph producers computed a join's id as
`f"join:{'+'.join(sorted(sources))}:{target}"` with no deduplication and no
escaping. Two or more `add_edge(sources, target)` declarations that share a
sorted source set and target — whether by exact repetition or permutation —
describe one AND-barrier at runtime (LangGraph fires the target once per
superstep regardless), but the producers emitted one join record per
declaration, so the independent validator correctly rejected the resulting
document for a duplicate join id. Separately, two differently-grouped source
lists whose members happen to contain the `+` delimiter (`["a+b", "c"]` vs.
`["a", "b+c"]`) could sort-and-join to the identical id string. Both
producers now group `waiting_edges` / `waitingEdges` by `(sorted sources,
target)`, emit exactly one join record per group, and escape each source id
(`\` → `\\`, then `+` → `\+`) before joining, so distinct groupings can no
longer collide. See
[ADR 0015](../decisions/0015-join-identity-deduplication-and-unambiguous-encoding.md).

**Hash and migration consequences: none.** `STRUCTURE_HASH_ALGORITHM_VERSION`
stays `"1"`. Every existing valid conformance fixture — none of which
declares a permuted, repeated, or `+`/`\`-bearing join — canonicalizes to the
identical id, `sources`, and hash as before this change;
`conformance/fixtures/multi-source-join` is unchanged byte-for-byte. The
inputs this change affects never had a valid prior document (the producer's
own output was already rejected by the validator), so there is no previously
valid hash to preserve or migrate. No document requires re-generation or
re-hashing to adopt this candidate.

A delimiter-bearing Python input that also collides with LangGraph's own
internal `+`-delimited channel naming keeps its existing upstream disposition:
`compiled_graph.get_graph(xray=0)` raises `InvalidUpdateError` before this
producer's logic runs, and `agt describe` reports extraction failure without
fabricating a document. The equivalent JavaScript input does not fail
upstream and now produces a valid, distinct document.

### `declare_children`: an explicit, construction-time child-relationship contract (Python only)

`agent_topology.langgraph` gains one new public function,
`declare_children(compiled_graph, children) -> compiled_graph`, letting a
factory that already holds every child object as a local variable state the
node-id-to-child mapping once, by direct object reference, right before
returning the compiled graph. `_mapped_compiled_child` accepts a declared
child (`compiled_graph.__agent_topology_children__.get(node_id)`) as a
second, independent evidence source alongside the existing direct-bound
check, adding the evidence kind `declared-child-call` alongside
`compiled-child`. This is additive: id derivation
(`f"{parent_graph_id}:{parent_node_id}"`), collision handling, the depth
budget, and the revision-2 `x-topology-interpretation` extension are all
unchanged, and a node with no declaration renders exactly as before,
`subgraph: unknown/identity-unavailable`. No TypeScript producer change: no
currently known TypeScript consumer exhibits the wrapped-call shape this
addresses, so `@agent-topology/langgraph`'s beta.5 build carries only the
join-identity fix above. See
[ADR 0014](../decisions/0014-explicit-construction-time-child-declaration.md).

#### Approved consumer relationship contract and pinned consumer commit

campaign-agent's `channel_concept` and `channel_production` factories bind
six real child calls (`prepare_brief`, `draft_copy`, `review_copy` in
`channel_concept`; `revise_copy`, `review_copy`, `prepare_copy_feedback` in
`channel_production`) through wrapper functions that call `child.invoke(...)`
rather than binding the compiled child directly — a shape ADR 0012's
direct-bound identity check cannot see. ADR 0014 records why the two
alternatives considered (framework-visible direct composition, and
LangGraph's own closure-based subgraph detection) cannot preserve campaign's
input projection, per-call-site context narrowing, error translation, and
result folding, and adopts `declare_children` instead. campaign-agent
requested the contract in
[campaign-agent#62](https://github.com/milocosmopolitan/campaign-agent/issues/62)
and adopted it at all six call sites in
[campaign-agent#63](https://github.com/milocosmopolitan/campaign-agent/pull/63),
with no change to any node function, state schema, or invocation call site.

This relationship was verified, not merely assumed, against campaign-agent
commit
[`a1532d5eed2d356792d5c3ee460d2bb8fb23db1e`](https://github.com/milocosmopolitan/campaign-agent/commit/a1532d5eed2d356792d5c3ee460d2bb8fb23db1e)
(the pinned merge of PR #63; no campaign-agent tag or release exists yet, so
this is a commit pin against remote `main`, not a released version) with
agent-topology inspected at commit `b89a704d577d831d9991ef9cdb7b2150d89bcb9c`
(main, past #185's merge). All six relationships were checked two ways —
depth-0 evidence kind is `declared-child-call`, and at depth 2 the
materialized child's node-id set is identical to that child's own standalone
`describe()` output (9/9 nodes matched for each of the six) — proving each
link points at the correct child, not merely a graph-count increase. See
[campaign-agent/review-2026-09-17-declared-children.md](../research/internal-consumer/campaign-agent/review-2026-09-17-declared-children.md).

## Known limitations and unverified claims

- **Dynamic-interrupt limits, unchanged.** The seven campaign dynamic
  `interrupt()` sites and git-agent's human-approval interrupt are absent
  from static `x-topology-interpretation` metadata by design: `describe()`
  extracts a graph's static construction-time structure and never executes or
  observes a runtime pause. This candidate's `declare_children` evidence is
  metadata read only at extraction time — it is not verified against actual
  runtime invocation, so a wrong declaration (a node that does not really
  invoke the object it declares) is a campaign-agent-owned correctness bug in
  the same sense a wrong `graph_id` already is, not something this producer
  can detect. See ADR 0014's "What we are explicitly not doing" and the
  [pre-beta review, R2](../research/internal-consumer/pre-beta-review-2026-09-17/README.md#r2-p1-for-full-campaign-support-real-children-are-hidden-by-wrappers).
- **Join-identity fix scope.** The `+` delimiter escape covers only the
  join-source segment of a join id; it is not a general collision-free
  encoding across the whole `join:<sources>:<target>` id shape (for example,
  a source or target id containing `:`), which remains unreported, untested,
  and out of this candidate's scope.
- **No LangGraph 1.3.x/1.4.x qualification claim.** This release does not
  expand either producer's tested-version manifest. Tracking future stable
  1.3.x/1.4.x releases against the qualification policy remains
  [#177](https://github.com/agent-topology/agent-topology/issues/177)'s scope,
  not this release's.
