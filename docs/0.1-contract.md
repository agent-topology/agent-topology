# 0.1 contract candidate

The `0.1` topology document is a **provisional contract candidate**. It is the
single contract implemented by the Python and TypeScript LangGraph producers and
used by the trace-correlation example. It is not a v1 stability promise or a claim
of vendor neutrality.

The checked-in [`agent-topology.schema.json`](../spec/agent-topology.schema.json) is
the authority for the document shape. The shared
[`conformance/fixtures`](../conformance/fixtures) are the authority for its graph
meanings. The [contract README](../spec/README.md) describes the validation API and
the complete field-level canonical and hash projection.

## Candidate contract

A `topologyVersion: "0.1"` document contains:

- provenance for the producing package, framework, source, and generation time;
- producer-wide `producerLimitations`;
- one or more graphs whose core structure contains nodes, edges, multi-source
  joins, entry nodes, and exit nodes;
- an explicit, versioned `structureHash`;
- graph-specific, element-local `completeness.gaps`; and
- optional producer or framework facts only under lower-case, namespaced `x-*`
  keys.

Multi-source joins are distinct from several independent incoming edges. Expanded
subgraphs refer to another graph by `subgraphId`; opaque subgraphs do not invent
contents. Static interrupt locations may be core node facts. LangGraph-specific
facts, including requested traversal depth, remain under `x-langgraph`.

### Canonical form

Canonical form sorts graphs, nodes, edges, joins, each join's sources, entry and
exit node identifiers, and node interrupt locations. It recursively sorts JSON
object keys and serializes as UTF-8 JSON with no insignificant whitespace. Arrays
in extensions and descriptive fields retain their declared order because the core
does not assign those arrays set semantics.

Both specification packages implement this same canonical form. Cross-language
tests compare the resulting canonical bytes, while the shared producer runners
compare the canonical document meaning.

### Structure-hash coverage

`structureHash.algorithm` is `sha256` and
`structureHash.algorithmVersion` is `"1"`. Hash version 1 covers:

- each graph `id`;
- node `id`, `type`, `subgraphId`, and `interrupts`;
- edge `id`, `source`, `target`, and `kind`;
- join `id`, `sources`, and `target`; and
- `entryNodeIds` and `exitNodeIds`.

It excludes graph names, provenance, producer limitations, completeness gaps,
extensions, labels, descriptive metadata, and the existing hash. The hash input is
the canonical JSON serialization of that projection, so declaration order does not
change the value and a multi-source join cannot collapse to separate incoming edges.

### Completeness

Producer limitations and gaps make different claims:

- A producer limitation names a category that a producer cannot observe in
  principle. It does not make an individual document incomplete.
- A gap records an unknown in the graph being described and identifies the affected
  graph element. A document is `complete` exactly when its `gaps` array is empty.

For example, dynamically raised interrupts are a current LangGraph producer
limitation. A router whose destinations were not declared creates an
`unknown-routing-targets` gap on that router and makes that document incomplete.
Python callers may use `strict=True` to receive `IncompleteTopologyError` for gaps;
the exception retains the canonical incomplete document. Producer limitations alone
do not make strict extraction fail.

## Independent version axes

These six values are independent. No value may be inferred from another, and the
four packages are not released as a monorepo unit.

| Axis                      | Candidate value in current source              | What changes it                                                 |
| ------------------------- | ---------------------------------------------- | --------------------------------------------------------------- |
| Document format           | `topologyVersion: "0.1"`                       | A change to the document contract                               |
| Structure hash            | `algorithm: "sha256"`, `algorithmVersion: "1"` | A change to canonical collection semantics or hashed properties |
| Python specification      | `agent-topology-spec` `0.1.0b1`                | A release of that distribution                                  |
| Python LangGraph producer | `agent-topology-langgraph` `0.1.0b1`           | A release of that distribution                                  |
| TypeScript specification  | `@agent-topology/spec` `0.1.0-beta.1`          | A release of that package                                       |
| LangGraph.js producer     | `@agent-topology/langgraph` `0.1.0-beta.1`     | A release of that package                                       |

The four source manifests carry their independently owned beta.1 package versions:
Python uses `0.1.0b1` and npm uses `0.1.0-beta.1`. The Python specification
distribution, `agent-topology-spec==0.1.0b1`, is available from PyPI. Publication of
the Python producer and both npm packages remains milestone 5 work.

## Compatibility and pre-1.0 change policy

Pre-1.0 means that incompatible changes remain possible, but they are explicit:

- A breaking core document change requires a `topologyVersion` transition, an
  updated schema and fixtures, and release notes that identify the incompatibility.
- A canonicalization or hash-coverage change requires a new
  `structureHash.algorithmVersion`. A transition may emit both old and new hashes;
  package and format versions do not change implicitly.
- A producer fix that extracts the existing contract more accurately changes only
  that producer package version. The document's hash value may correctly change,
  but the format and hash-algorithm versions stay fixed unless their contracts also
  changed.
- A validation, packaging, documentation, or other package-only release changes
  only the affected package version. Other packages do not receive coordinated
  version bumps.

Until milestone 5 publishes the public preview, changes are communicated in this
contract document, the governing ADRs, pull requests, and GitHub release notes for
qualified artifacts. There is no promise of backward compatibility across a future
format-version or hash-algorithm transition before v1.

## Known limitations and excluded consumers

- There is no vendor-neutral evidence yet. Python LangGraph and LangGraph.js are two
  language implementations of the same framework model; a structurally different
  framework is required before the core can claim neutrality.
- Dynamic interrupts inside node bodies cannot be discovered statically. Current
  producers report that as the non-blocking `dynamic-interrupts` limitation.
- Core sentinel nodes may be LangGraph-shaped, and conditional choice and runtime
  `Send` fan-out currently share one branch representation. Both remain provisional
  pending different-framework evidence.
- The contract distinguishes declared multi-source joins from independent edges but
  does not claim broader all/any join semantics that producers cannot observe.
- Rendering, policy verdicts, and path-coverage generation are intentionally outside
  the 0.1 contract and conformance suite. The trace-correlation example is the first
  proven consumer; it does not turn those excluded consumers into supported scope.
- Generic producer discovery, a producer-neutral CLI, and TypeScript CLI parity are
  intentionally excluded. TypeScript exposes importable APIs only.
- Registry availability is intentionally partial during milestone 5:
  `agent-topology-spec==0.1.0b1` is available from PyPI, while the Python producer
  and both npm packages remain pending.
