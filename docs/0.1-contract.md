# 0.1 contract candidate

The `0.1` topology document is a **provisional contract candidate**. It is the
single contract implemented by the Python and TypeScript LangGraph producers and
used by the trace-correlation example. It is not a v1 stability promise or a claim
of vendor neutrality.

The checked-in [`agent-topology.schema.json`](../spec/agent-topology.schema.json) is
the authority for the document shape. The shared
[`conformance/fixtures`](../conformance/fixtures) are the authority for its graph
meanings. The [contract README](../spec/README.md) describes the validation API and
the complete field-level canonical and hash projection.

## Candidate contract

A `topologyVersion: "0.1"` document contains:

- provenance for the producing package, framework, source, and generation time;
- producer-wide `producerLimitations`;
- one or more graphs whose core structure contains nodes, edges, multi-source
  joins, entry nodes, and exit nodes;
- an explicit, versioned `structureHash`;
- graph-specific, element-local `completeness.gaps`; and
- optional producer or framework facts only under lower-case, namespaced `x-*`
  keys.

Every `graphs[].id` is a unique document-local address selected by the producer
caller. `element.graphId` and `subgraphId` resolve to exactly one graph in the same
document. Callers composing several producer outputs assign distinct stable ids
during extraction rather than rewriting derived records afterwards. The compositor
supplies the new document's provenance, conservatively preserves every input
`producerLimitation`, carries every graph-specific gap, and retains input provenance
separately or under a compositor-owned `x-*` extension when needed. The LangGraph
producers retain `main` as the single-graph default and accept `graph_id` (Python) or
`graphId` (TypeScript) when another address is needed. Optional graph `name` is
descriptive and independent of identity; LangGraph authors control it through
`StateGraph.compile(name=...)`. See
[ADR 0011](decisions/0011-document-local-consumer-addressable-graph-ids.md).

Multi-source joins are distinct from several independent incoming edges. The
schema can link separately described subgraphs with `subgraphId`; opaque
subgraphs do not invent contents. The current LangGraph producers instead flatten
drawable expansion into the root graph. Current source records an
`expanded-subgraph-metadata` gap when children are expanded because their
declarations are not fully inspected; this correction is
[unreleased](../CHANGELOG.md#unreleased). Static interrupt locations may be core
node facts. LangGraph-specific facts, including requested traversal depth, remain
under `x-langgraph`.

### Canonical form

Canonical form sorts graphs, nodes, edges, joins, each join's sources, entry and
exit node identifiers, and node interrupt locations. It recursively sorts JSON
object keys and serializes as UTF-8 JSON with no insignificant whitespace. Arrays
in extensions and descriptive fields retain their declared order because the core
does not assign those arrays set semantics.

Both specification packages implement this same canonical form. Cross-language
tests compare the resulting canonical bytes, while the shared producer runners
compare the canonical document meaning.

### Numeric canonical form

A JSON number's canonical byte spelling is the ECMAScript `Number::toString`
result for its finite IEEE 754 `binary64` value (the same rule
[RFC 8785](https://www.rfc-editor.org/rfc/rfc8785) uses): signed zero
collapses to `0`, an integral value has no fraction (`1.0` spells `1`), and
the fixed/exponential switch happens outside the `-6 < n ≤ 21` decimal-exponent
range (for example `1e-6` spells `0.000001` but `1e-7` spells `1e-7`; `1e20`
spells `100000000000000000000` but `1e21` spells `1e+21`). `NaN` and
`±Infinity` remain rejected. A bare JSON integer literal beyond magnitude
`2^53` (for example, `9007199254740993`) is in the supported numeric domain:
it narrows to
its nearest `binary64` double, identically in both languages — the same
narrowing `JSON.parse` already performs in TypeScript — rather than being
rejected, so canonicalization stays closed under its own JSON round trip and
byte-identical across languages for every finite magnitude. Only a magnitude
too large for any finite `binary64` double to represent is rejected, via the
same path as the non-finite check. Every core field remains string-typed, and
every JSON number appears only inside an `x-*` extension, so this rule
governs full-document canonical bytes only; it does not change
`structureHash`. See [ADR 0009](decisions/0009-numeric-canonical-form.md) for
the byte oracle and the reasoning that keeps it out of the hash, and
[ADR 0010](decisions/0010-numeric-domain-parsed-value-narrowing.md) for the
domain-boundary narrowing rule.

### Structure-hash coverage

`structureHash.algorithm` is `sha256` and
`structureHash.algorithmVersion` is `"1"`. Hash version 1 covers:

- each graph `id`;
- node `id`, `type`, `subgraphId`, and `interrupts`;
- edge `id`, `source`, `target`, and `kind`;
- join `id`, `sources`, and `target`; and
- `entryNodeIds` and `exitNodeIds`.

It excludes graph names, provenance, producer limitations, completeness gaps,
extensions, labels, descriptive metadata, and the existing hash. The hash input is
the canonical JSON serialization of that projection, so declaration order does not
change the value and a multi-source join cannot collapse to separate incoming edges.

### Completeness

Producer limitations and gaps make different claims:

- A producer limitation names a category that a producer cannot observe in
  principle. It does not make an individual document incomplete.
- A gap records an unknown in the graph being described and identifies the affected
  graph element. A document is `complete` exactly when its `gaps` array is empty.

For example, dynamically raised interrupts are a current LangGraph producer
limitation. A router whose destinations were not declared creates an
`unknown-routing-targets` gap on that router and makes that document incomplete.
Python callers may use `strict=True` to receive `IncompleteTopologyError` for gaps;
the exception retains the canonical incomplete document. Producer limitations alone
do not make strict extraction fail.

## Independent version axes

These six values are independent. No value may be inferred from another, and the
four packages are not released as a monorepo unit.

| Axis                      | Candidate value in current source              | What changes it                                                 |
| ------------------------- | ---------------------------------------------- | --------------------------------------------------------------- |
| Document format           | `topologyVersion: "0.1"`                       | A change to the document contract                               |
| Structure hash            | `algorithm: "sha256"`, `algorithmVersion: "1"` | A change to canonical collection semantics or hashed properties |
| Python specification      | `agent-topology-spec` `0.1.0b3`                | A release of that distribution                                  |
| Python LangGraph producer | `agent-topology-langgraph` `0.1.0b3`           | A release of that distribution                                  |
| TypeScript specification  | `@agent-topology/spec` `0.1.0-beta.3`          | A release of that package                                       |
| LangGraph.js producer     | `@agent-topology/langgraph` `0.1.0-beta.3`     | A release of that package                                       |

The four source manifests prepare beta.3: Python uses `0.1.0b3` and npm uses
`0.1.0-beta.3`. This candidate is not published; see the
[candidate notes](releases/v0.1.0-beta.3.md). All eight beta.1 and beta.2 Python
and npm artifacts remain published and verified; see the
[beta.1](releases/v0.1.0-beta.1.md) and [beta.2](releases/v0.1.0-beta.2.md)
release notes. Installation commands throughout this repository continue to
select the published beta.2 versions until beta.3 passes registry
verification.

## Compatibility and pre-1.0 change policy

Pre-1.0 means that incompatible changes remain possible, but they are explicit:

- A breaking core document change requires a `topologyVersion` transition, an
  updated schema and fixtures, and release notes that identify the incompatibility.
- A canonicalization change requires a new `structureHash.algorithmVersion`
  only when it can alter the byte output of the version-1 hash projection, or
  when hash coverage itself changes ([ADR 0009](decisions/0009-numeric-canonical-form.md)).
  A canonicalization change confined to fields or extensions the projection
  excludes is a specification-package change instead. A transition may emit
  both old and new hashes; package and format versions do not change
  implicitly.
- A producer fix that extracts the existing contract more accurately changes only
  that producer package version. The document's hash value may correctly change,
  but the format and hash-algorithm versions stay fixed unless their contracts also
  changed.
- A validation, packaging, documentation, or other package-only release changes
  only the affected package version. Other packages do not receive coordinated
  version bumps.

Changes are communicated in this contract document, the [changelog](../CHANGELOG.md),
the governing ADRs, pull requests, and release notes for qualified artifacts.
There is no promise of backward compatibility across a future
format-version or hash-algorithm transition before v1.

## Known limitations and excluded consumers

- There is no vendor-neutral evidence yet. Python LangGraph and LangGraph.js are two
  language implementations of the same framework model; a structurally different
  framework is required before the core can claim neutrality.
- Dynamic interrupts inside node bodies cannot be discovered statically. Current
  producers report that as the non-blocking `dynamic-interrupts` limitation.
- Core sentinel nodes may be LangGraph-shaped, and conditional choice and runtime
  `Send` fan-out currently share one branch representation. Both remain provisional
  pending different-framework evidence.
- The contract distinguishes declared multi-source joins from independent edges but
  does not claim broader all/any join semantics that producers cannot observe.
- Ordinary edges preserve connectivity only. They do not specify first-trigger or
  once-only firing at a target with multiple incoming connections, suppression of
  a later trigger, or reset/rearming scope; a consumer must not infer either a
  per-trigger or a first-trigger-with-latch policy from edges alone. Declared
  multi-source joins retain their existing all-source-required meaning, unchanged.
  Experimental interpretation revision `1` (ADR 0008) adds no convergence
  firing-policy fact. This is an explicit beta.3 limitation; a stronger OR
  representation is future work requiring its own evidence and contract decision.
  See the [consuming guide's OR convergence section](guides/consuming-documents.md#or-convergence-and-first-trigger-firing).
- Rendering, policy verdicts, and path-coverage generation are intentionally outside
  the 0.1 contract and conformance suite. The trace-correlation example is the first
  proven consumer; it does not turn those excluded consumers into supported scope.
- Generic producer discovery, a producer-neutral CLI, and TypeScript CLI parity are
  intentionally excluded. TypeScript exposes importable APIs only.
