# Security policy

## Supported versions

The public preview is pre-1.0 and receives best-effort security maintenance. Only
the latest published release in the 0.1 line is considered for fixes; unreleased
commits, older 0.1 releases, and unsupported framework or runtime versions are not
maintained security branches. This policy is not a response-time or long-term-support
commitment.

| Version                      | Support                    |
| ---------------------------- | -------------------------- |
| Latest 0.1 release           | Best-effort security fixes |
| Older or unreleased versions | Not supported              |

## Reporting a vulnerability

Use GitHub's **Report a vulnerability** form in the repository Security tab to open
a private vulnerability report. Include the affected package and version, runtime,
framework version when relevant, impact, reproduction steps, and any suggested
mitigation. Do not include secrets or exploit details in a public issue.

The project will use the private report for follow-up and coordinated disclosure.
There is no guaranteed acknowledgement or remediation deadline. For ordinary bugs,
compatibility questions, and usage help, use GitHub Issues instead.
